# DropLens — Release Checklist

Work top to bottom before tagging a version. Every item is either a command that
must exit 0 or a document that must be updated; nothing here is optional for a
public or customer-facing build.

---

## 1. Code gates (must pass, on a clean checkout)

```bash
pip install -r requirements.txt
ruff check dropLens tests
python -m compileall -q dropLens tests
python tests/run_all.py --no-gui          # add test_gui on Windows: python tests/run_all.py
python scripts/check_readonly.py          # engine/ still cannot write user files
```

CI runs the same set (`.github/workflows/ci.yml`). A green CI run is necessary but
not sufficient — the GUI suite needs a display and only runs on Windows.

- [ ] `ruff` clean
- [ ] `compileall` clean
- [ ] `tests/run_all.py` all green (GUI suite included on Windows)
- [ ] `scripts/check_readonly.py` reports OK
- [ ] No new `except Exception: pass` without a logged warning

## 2. Supply chain

```bash
scripts/lock_requirements.sh          # or scripts/lock_requirements.ps1 on Windows
python -m pip_audit                   # review every advisory, record the decision
```

- [ ] `requirements-lock.txt` regenerated on the **target platform**
- [ ] `pip-audit` report reviewed; any unfixed advisory documented with a mitigation
- [ ] No dependency added without a reason recorded in `CHANGELOG.md`

## 3. Version and metadata (one source of truth)

- [ ] `APP_VERSION` bumped in `dropLens/__init__.py` **only**
- [ ] `CHANGELOG.md` has a dated section for the new version
- [ ] `README.md` roadmap checkboxes reflect reality
- [ ] `build/version_info.txt` is regenerated by `build.ps1` (never edited by hand)
- [ ] `installer/DropLens.iss` `#define MyAppVersion` default matches (it is only a
      fallback — `build_installer.ps1` passes the real value)

## 4. Build the artifacts (Windows)

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Clean -Version 2.3.0
powershell -ExecutionPolicy Bypass -File .\build_installer.ps1 -Version 2.3.0
```

- [ ] `dist\DropLens.exe` exists and its file properties show the new version
- [ ] `dist\Setup-DropLens-2.3.0.exe` exists
- [ ] Installer shows the license page and installs without admin (default)
- [ ] Per-machine variant builds when passed `/DMyPrivileges=admin`
- [ ] Installed app launches, indexes a small test folder, searches, and closes
- [ ] Uninstall leaves `%LOCALAPPDATA%\DropLens\catalog.db` intact

## 5. Signing

```powershell
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a `
    dist\DropLens.exe dist\Setup-DropLens-2.3.0.exe
signtool verify /pa /v dist\DropLens.exe
```

- [ ] Both artifacts signed with an OV/EV certificate
- [ ] `signtool verify` passes for both
- [ ] SHA-256 hashes computed and published with the release notes

```powershell
Get-FileHash dist\DropLens.exe, dist\Setup-DropLens-2.3.0.exe -Algorithm SHA256 |
    Select-Object Path, Hash
```

## 6. Functional smoke test (on a clean Windows VM)

- [ ] First run shows the onboarding wizard, scans a preset folder, window stays responsive
- [ ] Search: keyword, Name / Path / Content modes, category filter
- [ ] **Load more** returns new rows and never repeats one
- [ ] Semantic search restricted to a category returns only that category
- [ ] Preview pane renders content, AI summary, tags, favourite toggle, Notes…
- [ ] Export catalogue + export results produce valid CSVs (open in Excel)
- [ ] Translate works, or fails gracefully with offline-only on
- [ ] AI-enrich runs, progress advances, **Stop** actually stops, resume continues
- [ ] Assistant answer cites `[#id] file · p.N` and the citation opens the passage
- [ ] Tray icon appears, quick scan works, close-to-tray behaves as configured
- [ ] `droplens stats --json` and `droplens search "x" --json` work from a shell
- [ ] `droplens egress` shows exactly the expected outbound calls (or nothing)
- [ ] Offline-only mode blocks a cloud provider with a clear message

## 7. Documentation

- [ ] `docs/USER_GUIDE.md` matches the shipped UI
- [ ] `docs/SECURITY.md` matches the shipped network policy
- [ ] `docs/ENTERPRISE_DEPLOYMENT.md` commands verified against the built installer
- [ ] `docs/ARCHITECTURE_REVIEW.md` still labelled as the **2.0 baseline** (it is
      historical evidence, not a current defect list)
- [ ] `docs/IMPLEMENTATION_NOTES.md` updated with what shipped and what was deferred
- [ ] Any claim in `README.md` that the build does not support is removed

## 8. Publish

```bash
gh release create v2.3.0 \
  dist/Setup-DropLens-2.3.0.exe dist/DropLens.exe \
  --notes-file docs/release-notes-2.3.0.md
```

- [ ] `deploy/winget/AIONEXT.DropLens.yaml` updated with the version and real SHA-256
- [ ] Release notes list user-visible changes, known limitations and the hashes
- [ ] Upgrade path tested: install over the previous version, confirm the catalogue
      is retained and the schema migrates (`droplens stats --json` → `schema_version`)

---

## Post-release

- [ ] Watch issues for the first 72 hours
- [ ] Collect `droplens.log` + `droplens stats --json` from any crash report
- [ ] Record anything you had to work around in `docs/IMPLEMENTATION_NOTES.md`
